# Warraya

Keep every warranty and receipt in one place, and get a heads up before coverage runs out.

The product is a cross-platform mobile app (Expo / React Native, iOS + Android, in `mobile/`). The web app at warraya.com serves as the marketing site; its dashboard stays functional only until the app ships.

## Stack

- **Mobile app:** Expo (SDK 57) + React Native + TypeScript, expo-router, supabase-js, lottie-react-native; expiry reminders are local notifications scheduled on-device (30 and 7 days before expiry)
- **Backend:** Supabase (email OTP auth, Postgres with RLS, private storage bucket, edge functions)
- **Receipt scan:** the `extract-receipt` edge function sends the photo to the Claude API (Sonnet 5) and returns structured fields to pre-fill the form
- **Web (marketing + legacy dashboard):** Vite + React 18, Tailwind, hosted on Cloudflare Workers static assets

## Mobile development

Prerequisites: Xcode (iOS), Android Studio (Android), and **Node 22 LTS** (the Expo/Metro toolchain does not yet support Node 26; e.g. `brew install node@22` and prepend `/opt/homebrew/opt/node@22/bin` to `PATH` when working in `mobile/`). CocoaPods needs a UTF-8 locale on Ruby 4 (`export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`).

1. Terminal: `cd mobile && npm install`.
2. Optional: `cp .env.example .env` and fill `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_ANON_KEY`. With them blank the app runs in demo mode with seeded data.
3. Run a dev build (native modules mean Expo Go is not used):
   - iOS: `npm run ios`
   - Android: `npm run android`
4. Checks: `npm run typecheck` and `npm test` (Jest, pure-logic suites).

The native `mobile/ios` and `mobile/android` folders are generated by `expo prebuild` and are gitignored; `app.config.ts` is the source of truth. Version bumps happen in `app.config.ts` (`version`).

## Supabase setup (one time)

1. Create a project at supabase.com and note the URL and anon key.
2. Terminal, in this folder: `supabase link --project-ref <ref>` then `supabase db push`. The migration creates the `warranties` table, RLS policies, and the private `receipts` bucket.
3. Supabase dashboard, Authentication, Providers: make sure Email is enabled.
4. Supabase dashboard, Authentication, Email Templates: the Magic Link template must include `{{ .Token }}` so the six digit sign-in code is sent (shared by the mobile app and the web dashboard).
5. Terminal: `supabase secrets set ANTHROPIC_API_KEY=<your Anthropic API key>`
6. Terminal: `supabase functions deploy delete-account` and `supabase functions deploy extract-receipt`
7. Fill `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` in `mobile/.env` (and the `VITE_*` equivalents in `.env.local` / Cloudflare if the web dashboard is still in use).

## Web development and deploy

1. Terminal: `npm install`, then copy `.env.example` to `.env.local` and fill the `VITE_*` values.
2. Terminal: `npm run dev`

Every push to `main` builds and deploys the site via Cloudflare Workers Builds. For the deployed site to reach Supabase, set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` as build variables in Cloudflare (Workers and Pages, `warraya`, Settings, Build). Manual deploy: `npx wrangler login` once, then `npm run deploy`.

## Security

- Row Level Security on every table: users can only ever read or write their own rows, and policies are scoped to authenticated users with direct grants revoked from anonymous callers.
- Database CHECK constraints bound every user-supplied value (lengths, ranges, date ordering), so a buggy or hostile client can't write junk.
- The receipts bucket is private, capped at 10 MB per file, restricted to images and PDFs, and every object path is enforced to start with the owner's user id. Receipts are viewed through short-lived signed URLs.
- Edge functions validate their inputs, require a signed-in caller, and never leak upstream error details. The iOS app never talks to the Claude API directly; only the edge function holds the key.
- The site ships strict security headers, including a Content Security Policy, HSTS, and clickjacking protection (`public/_headers`).

## Structure

- `mobile/` Expo / React Native app (source of truth for the product), iOS + Android from one codebase
- `src/pages` web pages (Landing, SignIn, Dashboard, AddWarranty, WarrantyDetail, Terms, Privacy)
- `src/api`, `src/lib` web Supabase client, auth context, helpers
- `supabase/migrations` database schema
- `supabase/functions` edge functions (account deletion, receipt scan)
- `public` PWA manifest, icons, security headers
